# Импульс ФОРА UPS — Home Assistant

Пользовательская интеграция для мониторинга ИБП **Импульс ФОРА 3330** через Modbus TCP.
Одно устройство в Home Assistant, 66 сенсоров и 23 дискретных состояния.
Данные поступают локально, без облака и MQTT.

## Установка через Marketplace — Home Assistant 2026.11 и новее

В Home Assistant 2026.11 HACS заменён встроенным Marketplace. Устанавливать HACS
на этих версиях не нужно. [Официальная инструкция](https://www.home-assistant.io/integrations/marketplace/).

1. Откройте **Настройки → Marketplace**.
2. В правом верхнем углу нажмите **Добавить по ссылке / Add from link**.
3. Введите `https://github.com/langowen/ha-impuls-fora` и нажмите **Добавить**.
4. Если появится запрос, подключите GitHub, следуя подсказкам Home Assistant.
5. Откройте добавленный репозиторий и нажмите **Установить**.
6. Перезапустите Home Assistant, если Marketplace попросит об этом.
7. Для нового подключения откройте **Настройки → Устройства и службы → Добавить интеграцию → Импульс ФОРА**.
8. Введите IP вашего ИБП, порт Modbus TCP и адрес Modbus (Unit ID).

Репозиторий добавляется по ссылке; в общем каталоге Marketplace он пока не опубликован.
Файл `hacs.json` нужен и для Marketplace, поэтому остаётся в репозитории.
Установка через Marketplace пока не проверена на реальном экземпляре HA.

### HACS — Home Assistant до 2026.11

1. Откройте **HACS → меню ⋮ → Пользовательские репозитории**.
2. Добавьте `https://github.com/langowen/ha-impuls-fora`, тип **Интеграция**.
3. Найдите **Импульс ФОРА UPS**, скачайте и перезапустите Home Assistant.
4. Добавьте интеграцию через **Настройки → Устройства и службы**.

### Если интеграция уже установлена вручную

Существующее устройство и запись интеграции удалять не нужно.
Добавьте репозиторий в Marketplace (или HACS на старых версиях HA) для управления
установкой и обновлениями. Домен и уникальные идентификаторы сохранены.
Перед обновлением сделайте резервную копию HA. Если менеджер сообщит о конфликте
с ручной установкой, сохраните текст ошибки; не удаляйте запись устройства для обхода конфликта.

### Ручная установка

Скопируйте `custom_components/impuls_fora` в `/config/custom_components/impuls_fora`
и перезапустите Home Assistant. Затем добавьте интеграцию через интерфейс.

## Настройки

| Поле | Значение |
|---|---|
| IP-адрес | Адрес сетевой карты вашего ИБП |
| Порт | По настройкам сервера ИБП; по умолчанию в интеграции 1502 |
| Адрес Modbus | По настройкам ИБП; по умолчанию 1 |
| Интервал опроса | 10 секунд по умолчанию, диапазон 5–300 секунд |

Modbus TCP должен быть включён на сетевой карте. При добавлении проверяется чтение
измерений и дискретных состояний. Опрос выполняется последовательно, тремя запросами
за цикл. Если раньше использовали YAML-опрос того же устройства, отключите его.
В этой версии для изменения подключения запись интеграции нужно удалить и добавить заново.

## Датчики и состояния

- Вход, выход и байпас: напряжение, ток, частота и PF по фазам А/В/С.
- Полная, активная и реактивная выходная мощность, нагрузка по фазам.
- Заряд, напряжения, токи и температура АКБ, оставшаяся автономия и наработка.
- Режим питания и состояние батарей.
- Общая авария, разряд АКБ, байпас, перегрузка и другие сигналы.

Карта основана на экспорте **upsViewer ModBusTcp.xls**. Функция 04: адреса 0–2 и
44–106; функция 02: адреса 0–22. Полные адреса, типы и масштабы находятся в
[registers.json](custom_components/impuls_fora/registers.json) и
[alarms.json](custom_components/impuls_fora/alarms.json).
Токи АКБ декодируются как int16, заряд и автономия имеют масштаб 0,1.
Направление знака тока в исходной карте не описано. Канал АКБ «−» выводится отдельно.
Сенсоры отдельных силовых модулей пока не включены.

## Генератор в панели «Энергия» — с версии 0.3.0

Эта функция подходит для схемы **город/генератор → АВР → ФОРА → вся нагрузка**.
Она **выключена по умолчанию**. Без включения сущности генератора не создаются,
датчики сторонних интеграций не читаются. MyAVR не является зависимостью:
отдельно устанавливать его владельцам ФОРА без генератора не требуется.
Она не требует изменения сторонней интеграции MyAVR и не управляет генератором.
Расчёт использует активную входную мощность `Σ Uф × Iф × PFф` по регистрам
57–62 и 66–68. Так в оценку входят питание нагрузки, заряд АКБ и потери ИБП,
в отличие от мощности на выходе. Это оценка по телеметрии, не отдельный счётчик.

### Настройка

1. Обновитесь до 0.3.0 и перезапустите HA.
2. Откройте **Настройки → Устройства и службы → Импульс ФОРА → Настроить**.
3. Включите **«Включить учёт генератора (необязательно)»**.
   В поле **«Сенсор положения контактора АВР»** выберите
   `sensor.myavr_contactor_position` (либо фактический ID этого датчика у вас).
   Внутренние состояния должны быть `generator`, `mains`, `off`, `undefined`.
   Выбор обязателен при включении функции. Выключение прекращает расчёт;
   ранее созданные сущности могут остаться в реестре HA недоступными, история сохраняется.
4. Оставьте **«Добавлять отдельный вход байпаса» выключенным** для обычной
   работы через выпрямитель. Включайте его только если оба входа ИБП получают
   питание от того же АВР и ток байпаса измеряется отдельно от тока выпрямителя.
   Тогда дополнительно суммируются `U×I×PF` регистров 44–49, 53–55.
   В режиме байпаса без включённого учёта отдельного входа расчёт генератора
   недоступен: неполная мощность не выдаётся за полную.
5. Сохраните настройки. Выбор режима расчёта АКБ влияет только на батарею;
   функция генератора от него не зависит.

Появятся сущности:

| Название | ID | Единица |
|---|---|---|
| Мощность генератора (расчётная) | `sensor.fora3330_generator_power` | W |
| Выработка генератора (расчётная) | `sensor.fora3330_generator_energy` | kWh |

При `generator` учитывается входная мощность ИБП, при `mains`/`off` мощность
генератора равна нулю. При недоступности/неизвестном состоянии АВР или ошибке
чтения ИБП расчёты недоступны; пропущенная энергия не начисляется. Счётчик
сохраняется при перезапуске. Точность переключений ограничена опросом обоих
устройств. Если MyAVR показывает другие внутренние состояния, расчёт не включится.

### Добавление на панель

В **настройках панели «Энергия» → Солнечные панели → Добавить производство**
выберите **«Выработка генератора (расчётная)»**, мощность —
**«Мощность генератора (расчётная)»**, имя — **«Генератор»**.
Не включайте прогноз солнечной генерации для этого источника.
Это способ представить генератор как источник производства в HA 2026.11:
отдельного типа генератора нет, поэтому солнечная иконка и некоторые показатели
солнечной/неископаемой энергии могут быть неприменимы к топливному генератору.
Не используйте такие показатели как оценку его экологичности.

Городской счётчик должен учитывать только городскую сеть, до АВР — иначе
потребуется исключить двойной учёт генерации. При наличии потребителей вне
ИБП расчёт их не учитывает. Сам генератор во время прогрева без подключения
нагрузки не добавляет электрическую выработку дому. Функция не считает расход топлива.
Нельзя напрямую подставлять мощность ИБП без условия положения АВР: тогда
городская энергия ошибочно попадёт в генерацию.

## Панель «Энергия» — с версии 0.2.0

Добавлены шесть расчётных сенсоров. Старые сущности и их история сохранены.

| Сенсор | ID | Единица |
|---|---|---|
| Суммарная выходная мощность | `sensor.fora3330_output_power` | W |
| Мощность АКБ: плюс разряд, минус заряд | `sensor.fora3330_battery_power` | W |
| Мощность заряда АКБ | `sensor.fora3330_charge_power` | W |
| Мощность разряда АКБ | `sensor.fora3330_discharge_power` | W |
| Энергия заряда АКБ | `sensor.fora3330_charge_energy` | kWh |
| Энергия разряда АКБ | `sensor.fora3330_discharge_energy` | kWh |

### Включение расчёта батареи

По умолчанию расчёт АКБ отключён: карта не задаёт направление знака токов и
не объясняет, являются ли каналы АКБ +/− независимыми ветвями или дублирующими
измерениями. При отключённом расчёте батарейные сенсоры недоступны; суммарная
выходная мощность работает. Старое устройство удалять не нужно.

1. Обновите интеграцию и перезапустите HA.
2. **Настройки → Устройства и службы → Импульс ФОРА → Настроить**.
3. Выберите **«Направление по состоянию АКБ»**, если веб-интерфейс подтверждает
   состояния разряда/поддерживающего/ускоренного заряда (коды 326/451/331).
   В этом режиме используется модуль тока. Неизвестный статус, включая ожидание
   с ненулевым током, делает батарейные расчёты недоступными.
   Альтернатива после проверки токов при реальном заряде/разряде — выбрать,
   что означает положительный ток: заряд либо разряд. Настройка одинакова для двух каналов.
4. Выберите используемые каналы. **«Две независимые ветви»** подходит только
   если +/− действительно измеряют разные ветви батареи. Если измерение
   дублируется, используйте один соответствующий канал. Проверьте это по
   документации/схеме именно вашего ИБП, а не по совпадению чисел.

Формула двух ветвей: `P = U+ × I+ + U− × I−` с раздельным направлением потоков.
В режиме по состоянию суммируются `abs(U+ × I+) + abs(U− × I−)`.
Не используется произведение суммы напряжений на сумму токов.
Суммарная выходная мощность = сумма активных мощностей фаз 88/89/90,
переведённая в W; она не является мощностью разряда АКБ.

### Что выбрать в настройках «Энергия → Аккумуляторная батарея»

| Поле | Сенсор / значение |
|---|---|
| Энергия, поступающая из батареи | Энергия разряда АКБ |
| Энергия, поступающая в батарею | Энергия заряда АКБ |
| Тип измерения мощности | Два датчика |
| Мощность из батареи | Мощность разряда АКБ |
| Мощность в батарею | Мощность заряда АКБ |
| Уровень заряда | Заряд АКБ (`sensor.fora3330_r101`) |
| Ёмкость | Известная полезная ёмкость в kWh; не подставляйте Ah |

Альтернативно выберите «Стандартный» и «Мощность АКБ»: положительный поток — разряд.
После включения расчёта дайте HA время сформировать статистику для новых сенсоров.
Если ID заняты, используйте фактические ID на странице устройства.

Энергия — оценка на стороне **DC батареи**, не AC-счётчик с учётом потерь инвертора.
Счёт ведётся с момента включения функции, исторические значения не восстанавливаются.
Интегрирование методом левых прямоугольников выполняется каждый успешный опрос,
даже при неизменной мощности. Значения хранятся в `.storage` отдельно по устройству
и сохраняются перед публикацией каждого успешного расчёта; между перезапусками
восстанавливаются только итоги, не временной интервал.
При пропуске связи, неизвестном состоянии или паузе более 2,5 интервалов опроса
пропущенная энергия не начисляется. Это предотвращает выдуманные кВт·ч, но
означает недоучёт за время отсутствия данных. Счётчики не обнуляются при изменении
параметров, поэтому перед использованием в «Энергии» проверьте настройки.
У счётчиков `device_class: energy`, `state_class: total` без `last_reset`;
у мощности `device_class: power`, `state_class: measurement`.

## Карточка устройства

Добавьте на панель карточку **«Вручную»** и вставьте содержимое
[dashboard-card.yaml](dashboard-card.yaml). Дополнения для интерфейса не требуются.
Карточка показывает заряд, автономию, таблицу трёх фаз, батареи и аварии.
В комплекте используется sensor.fora3330_rN / binary_sensor.fora3330_dN.
Если HA добавил суффикс из-за совпадения имён или вы переименовали сущности,
исправьте ссылки в карточке. Для нескольких ИБП потребуется отдельная копия карточки
с фактическими ID второго устройства. Карточка добавляется отдельно от интеграции.

## Доступность и ограничения

При ошибке любого запроса весь снимок отклоняется, сущности становятся недоступными.
После восстановления обмена они обновляются автоматически. Сигнал «Нарушение связи»
адреса 0 — состояние, сообщаемое самим ИБП, а не проверка соединения HA с сетевой картой.
Неизвестные коды состояний отображаются с числовым кодом.
Команды управления и запись регистров не выполняются.

Пользователь подтвердил работу версии 0.1.0 на своём ИБП ФОРА 3330.
Версия 0.1.1 исправляет названия фаз и добавляет оформление репозитория для HACS.
Другие модели и прошивки не проверены. Минимальная заявленная версия HA — 2025.8;
проверки на всей матрице версий HA пока нет. Используется pymodbus, предоставляемый
встроенной интеграцией Modbus Home Assistant.

## Диагностика

Если подключение не удаётся, проверьте IP, порт и Unit ID в настройках сервера
Modbus сетевой карты и доступность устройства из сети HA. При сообщении о неизвестном
коде или неверных значениях приложите к issue версию HA, прошивку сетевой карты,
название параметра и одновременные показания HA/веб-интерфейса.
Не публикуйте пароли и токены.

## Разработка

`python -m unittest discover -s tests -v`

Тесты проверяют декодирование, масштабы, адреса запросов, Unit ID,
короткие ответы, ошибки и восстановление соединения, последовательный обмен.
Полная проверка жизненного цикла в HA пока не автоматизирована.
