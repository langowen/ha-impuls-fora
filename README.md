# Импульс ФОРА UPS — Home Assistant

Пользовательская интеграция для мониторинга ИБП **Импульс ФОРА 3330** через Modbus TCP.
Одно устройство в Home Assistant, 66 сенсоров и 23 дискретных состояния.
Данные поступают локально, без облака и MQTT.

## Установка через HACS

1. Откройте **HACS → меню ⋮ → Пользовательские репозитории**.
2. Добавьте `https://github.com/langowen/ha-impuls-fora`, тип **Интеграция**.
3. Найдите **Импульс ФОРА UPS**, скачайте и перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Импульс ФОРА**.
5. Введите IP вашего ИБП, порт Modbus TCP и адрес Modbus (Unit ID).

Репозиторий добавляется в HACS вручную; в общий каталог HACS он пока не включён.

### Переход с ручной установки

Удалять устройство и сущности не нужно. Добавьте репозиторий в HACS и установите
интеграцию поверх существующей папки `custom_components/impuls_fora`, затем перезапустите HA.
Домен и уникальные идентификаторы сохранены. Создайте резервную копию HA перед обновлением.

### Ручная установка

Скопируйте `custom_components/impuls_fora` в `/config/custom_components/impuls_fora`
и перезапустите Home Assistant. Затем добавьте интеграцию через интерфейс.

## Настройки

| Поле | Значение |
|---|---|
| IP-адрес | Адрес сетевой карты вашего ИБП |
| Порт | По настройкам сервера ИБП; по умолчанию в интеграции 1502 |
| Адрес Modbus | По настройкам ИБП; по умолчанию 1 |
| Интервал опроса | 10 секунд по умолчанию, диапазон 5–300 секунд |

Modbus TCP должен быть включён на сетевой карте. При добавлении проверяется чтение
измерений и дискретных состояний. Опрос выполняется последовательно, тремя запросами
за цикл. Если раньше использовали YAML-опрос того же устройства, отключите его.
В этой версии для изменения подключения запись интеграции нужно удалить и добавить заново.

## Датчики и состояния

- Вход, выход и байпас: напряжение, ток, частота и PF по фазам А/В/С.
- Полная, активная и реактивная выходная мощность, нагрузка по фазам.
- Заряд, напряжения, токи и температура АКБ, оставшаяся автономия и наработка.
- Режим питания и состояние батарей.
- Общая авария, разряд АКБ, байпас, перегрузка и другие сигналы.

Карта основана на экспорте **upsViewer ModBusTcp.xls**. Функция 04: адреса 0–2 и
44–106; функция 02: адреса 0–22. Полные адреса, типы и масштабы находятся в
[registers.json](custom_components/impuls_fora/registers.json) и
[alarms.json](custom_components/impuls_fora/alarms.json).
Токи АКБ декодируются как int16, заряд и автономия имеют масштаб 0,1.
Направление знака тока в исходной карте не описано. Канал АКБ «−» выводится отдельно.
Сенсоры отдельных силовых модулей пока не включены.

## Карточка устройства

Добавьте на панель карточку **«Вручную»** и вставьте содержимое
[dashboard-card.yaml](dashboard-card.yaml). Дополнения для интерфейса не требуются.
Карточка показывает заряд, автономию, таблицу трёх фаз, батареи и аварии.
В комплекте используется sensor.fora3330_rN / binary_sensor.fora3330_dN.
Если HA добавил суффикс из-за совпадения имён или вы переименовали сущности,
исправьте ссылки в карточке. Для нескольких ИБП потребуется отдельная копия карточки
с фактическими ID второго устройства. Карточка добавляется отдельно от интеграции.

## Доступность и ограничения

При ошибке любого запроса весь снимок отклоняется, сущности становятся недоступными.
После восстановления обмена они обновляются автоматически. Сигнал «Нарушение связи»
адреса 0 — состояние, сообщаемое самим ИБП, а не проверка соединения HA с сетевой картой.
Неизвестные коды состояний отображаются с числовым кодом.
Команды управления и запись регистров не выполняются.

Пользователь подтвердил работу версии 0.1.0 на своём ИБП ФОРА 3330.
Версия 0.1.1 исправляет названия фаз и добавляет оформление репозитория для HACS.
Другие модели и прошивки не проверены. Минимальная заявленная версия HA — 2025.8;
проверки на всей матрице версий HA пока нет. Используется pymodbus, предоставляемый
встроенной интеграцией Modbus Home Assistant.

## Диагностика

Если подключение не удаётся, проверьте IP, порт и Unit ID в настройках сервера
Modbus сетевой карты и доступность устройства из сети HA. При сообщении о неизвестном
коде или неверных значениях приложите к issue версию HA, прошивку сетевой карты,
название параметра и одновременные показания HA/веб-интерфейса.
Не публикуйте пароли и токены.

## Разработка

`python -m unittest discover -s tests -v`

Тесты проверяют декодирование, масштабы, адреса запросов, Unit ID,
короткие ответы, ошибки и восстановление соединения, последовательный обмен.
Полная проверка жизненного цикла в HA пока не автоматизирована.
